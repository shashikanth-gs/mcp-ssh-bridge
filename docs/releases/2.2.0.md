# SSH MCP Bridge 2.2.0

Release date: 2026-09-11

## Summary

Version 2.2.0 replaces the ad hoc HTTP authentication and legacy transport
with framework-native FastMCP security, and returns a compact, typed result
from `execute_command`.

Previously, a configured API key protected the REST compatibility routes but
not the primary `/mcp` endpoint: `/mcp` could be reached without
authentication whenever OAuth was not configured. This release closes that
gap by building one authentication policy — static API key, JWT/JWKS, Auth0,
or a mix during migration — and applying it to both `/mcp` and every
`/api/v1/*` REST route.

## Authentication

- `auth_mode: auto | none | api_key | oidc` selects the policy explicitly.
  Invalid explicit configuration (e.g. `auth_mode: api_key` without a key)
  now fails startup rather than silently exposing an anonymous service.
- `api_key` — FastMCP `StaticTokenVerifier`. Documented by FastMCP as a
  compatibility/internal mechanism; prefer JWT/JWKS or Auth0 for production.
- `oidc` with `oauth.provider: jwt` — FastMCP `JWTVerifier` wrapped in
  `RemoteAuthProvider`, which also publishes RFC 9728 protected-resource
  metadata and a matching `WWW-Authenticate` challenge.
- `oidc` with `oauth.provider: auth0` — FastMCP `Auth0Provider` for
  interactive OAuth proxying.
- `auto` mode combines whichever of the above are configured via `MultiAuth`.

See [CONFIGURATION.md](../CONFIGURATION.md#http-security-and-authentication)
for the full option reference and migration examples.

## HTTP Transport and Safety Defaults

- The MCP endpoint moves from legacy HTTP+SSE to stateless Streamable HTTP.
- The default bind changes from `0.0.0.0` to `127.0.0.1`. A non-loopback bind
  requires an explicit `allowed_hosts` list (no `*`) and, in most cases,
  authentication.
- `Host` and browser `Origin` headers are validated before MCP dispatch to
  mitigate DNS rebinding; wildcard CORS origins are rejected for non-loopback
  binds.
- Requests are rate-limited per authenticated client identity
  (`rate_limit_per_minute`, default 60), enforced on both `/mcp` and the
  `/api/v1/*` REST routes as two independently-tracked budgets.
- `execution_mode: shell` (a persistent, process-global shell session) is
  rejected in HTTP mode by default, since that state would otherwise be
  shared across unrelated HTTP callers. Use `exec`, or set
  `allow_shared_shell_sessions: true` for an explicitly single-principal
  deployment.

## Command Results

`execute_command` now returns a typed `CommandResult`:

```json
{
  "host": "web-server",
  "output": "...",
  "success": true,
  "exit_status": 0
}
```

- The submitted `command` is no longer included in the response or in
  service/SSH execution logs — it was already present in the tool-call
  arguments, so echoing it back only duplicated data and risked retaining
  secrets in logs.
- `exit_status` is now always present (previously omitted on success).
- Persistent shell-mode commands report their real exit status, captured via
  a unique per-call marker, instead of always reporting success.

## Error Handling

HTTP mode masks unexpected MCP and REST error details from clients. This
release tunes what counts as "unexpected": ordinary, safe-to-show conditions
— an unknown host, a path-policy violation, a dropped SSH connection, a
command timeout — are still delivered to the client with their real message
on both `/mcp` and REST, matching each other. Only genuinely unexpected
exceptions are masked into a generic error.

## Continuous Integration

This release adds GitHub Actions CI: the test suite runs on Python
3.10-3.13, and `black`/`isort` formatting is checked, on every pull request
and every push to `main`. There was no automated status check on this
repository before this release.

## Compatibility Notes

- `execute_command` responses no longer include a `command` field.
- `execute_command.exit_status` is now always present.
- Legacy HTTP+SSE clients must move to Streamable HTTP.
- HTTP mode binds to loopback by default; remote binds need `allowed_hosts`.
- JWT/JWKS mode requires an externally visible HTTPS `oauth.base_url` (or
  `BASE_URL`).
- Remote wildcard CORS (`cors_origins: ["*"]`) is rejected.
- Hosts using `execution_mode: shell` in HTTP mode need `exec`, or explicit
  `allow_shared_shell_sessions: true`.

## Known Limitations

- Static API keys remain a compatibility/internal mechanism; FastMCP
  documents them as unsuitable for general internet-facing production
  because token material is held in process memory.
- Remote deployments must terminate TLS at a trusted reverse proxy or load
  balancer; this release does not add TLS termination itself.
- Auth0 multi-instance deployments need a stable `JWT_SIGNING_KEY` and
  persistent encrypted client storage; the default in-memory storage is
  single-instance only.
- REST and `/mcp` rate limits are two independent counters with the same
  per-minute budget, not one shared total.
- There is still no per-host or per-tool authorization: any authenticated
  bearer token can act on every configured host and tool.
