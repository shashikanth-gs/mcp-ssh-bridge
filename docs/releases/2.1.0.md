# SSH MCP Bridge 2.1.0

Release date: 2026-09-02

## Summary

Version 2.1.0 adds bidirectional SFTP file transfer to SSH MCP Bridge.

Agents can now upload files from the MCP server host to configured SSH targets and download files from SSH targets back to the MCP server host. The feature works in both STDIO and HTTP deployments, with explicit path allowlists and file size limits.

This release also updates the MCP runtime stack to FastMCP 4.0.1 and MCP SDK
2.1.1. FastMCP 4 requires Python 3.10+, so SSH MCP Bridge now requires Python
3.10 or newer.

## New MCP Tools

- `get_file_transfer_config`
- `stat_remote_path`
- `list_remote_directory`
- `download_file`
- `upload_file`

## HTTP Support

HTTP mode supports the same transfer operations, but transfers are server-side:

```text
MCP client -> HTTPS -> SSH MCP Bridge host -> SFTP -> SSH target host
```

In HTTP mode, `local_path` means a path on the machine running `ssh-mcp-bridge`. It does not mean a path on the laptop or remote MCP client connecting over HTTP.

The HTTP API includes:

- `GET /api/v1/file-transfer-config`
- `POST /api/v1/remote/stat`
- `POST /api/v1/remote/list`
- `POST /api/v1/download`
- `POST /api/v1/upload`

Use a staging directory on the MCP server host:

```yaml
security:
  allowed_local_paths:
    - "/var/lib/ssh-mcp-bridge/transfers"
  allowed_remote_write_paths:
    - "~"
    - "/tmp"
  max_file_transfer_mb: 100
```

For Docker deployments, mount the staging directory:

```bash
docker run -d \
  --name ssh-mcp-bridge \
  -p 8080:8080 \
  -v $(pwd)/config.yaml:/app/config.yaml:ro \
  -v ~/.ssh:/home/mcpuser/.ssh:ro \
  -v ssh-mcp-transfers:/var/lib/ssh-mcp-bridge/transfers \
  shashikanth-gs/mcp-ssh-bridge:latest
```

## STDIO Support

In STDIO mode, `ssh-mcp-bridge` runs on the same machine as the MCP client, so `local_path` usually points to the laptop filesystem:

```text
MCP client and bridge on laptop -> SFTP -> SSH target host
```

Example:

```text
upload_file(
  host="web-server",
  local_path="/Users/me/Downloads/app.env",
  remote_path="/tmp/app.env",
  overwrite=true
)
```

## Security Notes

- Upload sources must be under `allowed_local_paths`.
- Download destinations must be under `allowed_local_paths`.
- Remote upload destinations must be under `allowed_remote_write_paths`.
- Transfers larger than `max_file_transfer_mb` are rejected.
- Existing files require `overwrite=true`.
- Transfer results return metadata and SHA-256 hashes, not file contents.

## Known Limitations

- Single-file transfer only.
- No direct browser/laptop multipart binary upload endpoint for remote HTTP clients yet.
- No expiring HTTP download URLs yet.
- Directory sync is not implemented.

Future work can add transfer IDs, MCP resources for downloaded files, HTTP upload/download endpoints, object storage signed URLs, and directory transfer support.
